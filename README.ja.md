# research-clerk-md（日本語要約）

「調べて、まとめて」を頼む相手として AI アシスタントに常駐させる指示ファイルです。`RESEARCH_CLERK.md` を Claude Code なら `CLAUDE.md` に、他のツールならシステム指示欄に貼って使います。命令の形ではなく「わたしはこういう仕事の仕方をする」という自己記述で書いてあり、同じ規則を命令形で書いた比較用の版も同梱しています。

**必ず出荷票（`SHIPPING_LABEL.md`）とセットで読んでください。** 出荷票は薬の説明書と同じ型で、効能は書きません。設計上見えるはずのもの・実際に測ったこと・穴、だけを書いています。

## 先に読んでほしいこと

- この md が「正直さを上げる」とも「自己記述の方が命令形より効く」とも主張していません。今のところの比較（試験2本・3腕・各1走）では、md なしの素でも同じ圧を断りました。差が出た1点は命令形の方が良い結果でした。
- 圧のかかっていない普通の依頼での挙動は未測定です。
- 試験はツールなし・合成の束で走らせているので、md 自身が勧める機械照合（取得時刻とツールログの突合）は一度も適用できていません。
- 生出力は `raw/`（日本語）にあります。n=1 は全部読めます。環境は一人・一構成（Claude Code CLI 2.1.267・モデル未固定・日本語の依頼）。
- 先行事例は探した範囲で「手順を起きた順に申告」「要約でタグを落とさん」を書いた指示ファイルは見つかっていません。見つからん＝無い、ではありません。最も近いのは drydock の grounding protocol（README 参照）。

## 中身

| ファイル | 何か |
|---|---|
| `RESEARCH_CLERK.md` | 本体（自己記述版）。倒れ方5つ＋渡す時の1つ／出所タグ3種（行為で決まる）／日付／一次・二次／数で押さない／手順は起きた順／取れなかったものは取れなかったと／材料が先・読みが後／要約でタグを落とさない／訂正／出典リスト／仕事の終わり |
| `RESEARCH_CLERK_command_form.md` | 同じ規則の命令形。対照用。商品ではない |
| `SHIPPING_LABEL.md` | 出荷票。見えるはずのもの／向く用途・向かない用途／既知の穴6つ／未検証／相方／わざと塞がない穴1つ／対抗テスト2本の実況／先行事例 |
| `raw/` | 試験の依頼文（合成の束・明記済み）・2ターン目の再押し・各腕の返答 |
